# Architecture

The Python package owns investigation state and LangGraph orchestration. The Go service provides read-only synthetic incident health, metrics, and log observations over local HTTP. Later, an MCP adapter will expose diagnostics to the graph. No production infrastructure is connected.

Current flow: `START -> receive_incident -> classify -> severity_policy -> END` by default. An explicit `retrieval_mode = "history"` routes through `retrieve_history` before classification when a retriever is injected. An explicit `classification_mode = "llm"` routes through `llm_classify` before policy when a model is injected. An explicit `investigation_mode = "simulated"` routes after policy through a deterministic plan, one diagnostic read, evidence evaluation, and a bounded loop before ending. Intake validates the report and initializes counters. The caller supplies a `thread_id` so `InMemorySaver` can checkpoint execution.

`IncidentReport` records the incoming facts. `InvestigationState` carries classification and policy results, historical matches, diagnostic checks and counters, current evidence, fixed failure categories, and a stop reason. Each evidence item records its incident, service, source kind, stable ID, source reference, observation time, and bounded observation. Historical matches and tool failures are stored separately and cannot become current evidence. The OpenAI adapter can be injected into the optional model route; the default path remains local and needs no API key or embedding model.

Target flow: `incident input -> optional historical retrieval -> baseline and/or LLM classification -> investigation plan -> diagnostic tools -> evidence evaluation -> conditional loop -> diagnosis -> human approval -> simulated remediation -> verification -> report`.

`graph.py` owns topology, conditional edges, cycle bounds, and checkpoint compilation. `nodes/` owns one decision or effect per node. `schemas.py` owns graph state contracts; a future LLM classifier gets its own structured output schema, which is validated and mapped into state. `tools/` owns external clients. The Go service supplies simulated observations; an MCP adapter may expose those same diagnostic capabilities later. A historical incident match carries similarity and provenance, but is never evidence that the current incident has the same cause.

Phase 4 uses a validated fixture store and `GET /incidents/{id}/health`, `/metrics`, and `/logs` on the loopback Go service. Process `/health` remains independent. The Python client restricts requests to those three reads on a loopback HTTP origin and validates each response. The opt-in graph checks health, metrics, and logs in that order, retries only transient failures once, and stops after at most three rounds or six actual client attempts. Empty data and failures yield no evidence. Phase 5 adds evidence-grounded diagnosis. Phase 6 adds an interrupt before remediation and resumes only after an explicit decision. Phase 7 replaces process-local checkpointing for restart safety. No multi-agent layer is planned. See `ROADMAP.md` for acceptance criteria.
