# Decisions

- **Deterministic baseline first:** a small rule set makes state transitions and failure cases testable before model calls. It is not a production classifier.
- **TypedDict state:** follows LangGraph's typed state pattern with minimal dependencies. Runtime input validation is explicit at intake.
- **Optional LangChain:** reserved for provider integration when model calls begin; the foundation requires no API key.
- **In-memory checkpoints:** temporary foundation choice; restart loses state. Durable checkpoints are required before production deployment.
- **Local-only Go server:** avoids exposing simulated remediation endpoints when they arrive.
- **Separate LLM interpretation and policy:** structured model output will report interpreted impact and uncertainty; deterministic policy will enforce severity. Model output cannot invent metrics.
- **Ground severity in the current report:** the severity policy keeps a known baseline result unless the report explicitly negates that scope. When the baseline is `unknown`, it accepts only verbatim source references from the incident summary and maps their scope with fixed rules. Unsupported, missing, negated, or conflicting impact remains `unknown`; a model's recommended severity never grants remediation approval. The fixed scope vocabulary has the same paraphrase limitations as the baseline.
- **Validate classifier output at runtime:** retain a separate `TypedDict` output contract and use Pydantic's `TypeAdapter` to enforce types and an optional confidence range of 0–1. Declare Pydantic and typing-extensions directly because the schema uses them.
- **Inject the classifier model:** keep the model call behind a small `Protocol` so fake-model tests run without credentials. Return interpreted output separately from graph state and severity policy.
- **Optional OpenAI adapter:** use LangChain's OpenAI integration behind the existing model protocol. The system prompt requires exact report quotes for impact claims; LangChain requests structured output, and Pydantic still validates the result. Disable provider-internal retries so the classification node owns the bounded retry count. Require explicit model and API-key environment variables only when constructing the adapter.
- **Explicit model routing:** the graph always computes the baseline first, then routes to the model only for `classification_mode = "llm"` with an injected model. Both routes pass through deterministic severity policy. A missing model or unrecognized mode fails visibly; the default route remains local.
- **Bounded classification recovery:** repair invalid structured output with at most one grounded model retry; retry each transient provider call at most three times with exponential backoff. A future provider adapter must translate temporary rate limits or unavailability into `TransientProviderError`. After exhaustion, record the reason and use the deterministic baseline, keeping ambiguous impact `unknown` for human review. Classification is never remediation approval.
- **Historical retrieval is context:** similar past incidents can guide questions but cannot prove current impact or cause. Start with a local sentence-transformer and in-memory ranking; defer pgvector until evaluation supports it.
- **Validate history at load time:** keep the synthetic history separate from labeled evaluation cases. Reject malformed JSON, missing incident fields, duplicate IDs, and records without synthetic provenance before building any retrieval index; keep IDs and summaries paired in file order.
- **Keep embeddings optional and local:** load Sentence Transformers only when constructing the embedding adapter, so baseline and tests need no model package or download. Normalize query and document vectors consistently, validate output dimensions, and allow a fake model in tests. Similarity scores will be retrieval context only.
- **Rank history in memory first:** validate and snapshot the synthetic records, embed service, summary, symptoms, and impact once, and use cosine similarity for top-k matches. Leave past causes and resolutions out of search text because the current cause is not known. Return the complete past record with provenance and a score; break ties by stable ID. Never use a retrieved match to set severity or claim the current cause. Delay FAISS until ranking can be evaluated.
- **Opt-in graph retrieval:** `retrieval_mode = "history"` requires an injected retriever and runs before classification. The default skips retrieval and needs no model weights. Validate scored synthetic matches before state update; if retrieval fails, record `retriever_error`, clear matches, and continue classification. Pass past summaries, causes, and resolutions to the optional classifier only as labeled context for missing questions. Current-report quotes remain the sole basis for impact and severity policy.
- **Freeze retrieval query v1:** keep 21 project-authored, single-relevant-ID queries separate from history and classification evaluation data. Report Recall@k, MRR@k, failures, and latency, with data hashes and model weight hash. The first local MiniLM run found 20/21 labels at rank 1; preserve the payment-retry miss and create a new query version for later changes. These labels lack independent review, so no production retrieval claim follows.
- **Evaluation before claims:** compare baseline, LLM, and LLM plus retrieval on fixed synthetic labels, with latency and failure measurements alongside quality metrics.
- **Keep model routing opt-in after Phase 2:** the frozen v1 run favored GPT-6 Luna on final severity, but the separate challenge run had low severity accuracy and weaker symptom precision. Both sets are small and synthetic; the challenge set was also used for a policy correction. Keep the baseline default and make no generalization or production-performance claim. Record provider rates as explicit evaluator inputs, not hard-coded prices.
- **Freeze evaluation v1:** keep the 24-case dataset and its reference labels unchanged after the baseline review; make a new version for corrections so comparisons remain reproducible.
- **Single graph:** conditional routing and bounded cycles are sufficient for this workflow; no multi-agent abstraction is needed.
- **Read-only incident health first:** start Phase 4 with validated, embedded synthetic health snapshots in the loopback Go service. Keep process `/health` independent of incident health. Restrict incident IDs to the `diag-` namespace, reject malformed or duplicate fixtures at startup, and return fixed JSON errors for invalid or unknown IDs. An `unknown` snapshot with no checks represents missing data; it is not evidence of a healthy service. Metrics, logs, diagnosis, and remediation remain separate work.
- **Fixed incident metrics before Prometheus:** embed validated numeric snapshots keyed by the same synthetic incident IDs and services as health. Encode the observation window as a duration string, keep an empty metrics list distinct from a measured zero, and return defensive copies. The mock service does not scrape or query Prometheus; a read-only local adapter can be added after the deterministic diagnostic loop is tested.
- **Bounded synthetic logs:** embed fixed log snapshots keyed by the same incident IDs, services, and observation times as health and metrics. Reject malformed entries, duplicate IDs, and future timestamps at startup. Serve defensive copies through a read-only route with a default limit of 20 and a maximum of 50; an empty entry list means missing observations. Logs contain no diagnosis labels and cannot authorize remediation.
- **Local diagnostic client boundary:** the Python HTTP adapter accepts only `health`, `metrics`, and `logs` for validated synthetic IDs and a loopback HTTP origin. It validates response shape and incident/service identity and reports fixed timeout, unavailable, not-found, or invalid-response categories without passing raw network errors into state. The client performs one request per call; the opt-in graph loop owns retries and counts every attempt against its budget. `httpx` is a direct dependency; the default classifier makes no network request.
- **Opt-in bounded investigation:** `investigation_mode = "simulated"` requires an injected diagnostic client and a `diag-` incident ID. After severity policy, a deterministic plan reads health, metrics, and logs in order. The graph counts every client attempt, retries only timeout or unavailable once per read, and stops after at most three rounds or six attempts; 404 stops immediately. It stores current observations with stable source references and tool failures separately, then hands off to diagnosis. A small CLI creates a fresh thread for each local demonstration. The default graph route makes no diagnostic calls.
- **Phase 4 acceptance on local fixtures:** accept the read-only diagnostic loop after uncached Go tests, Python contract and graph tests, and one local CLI run per fixed fixture plus unknown-ID and failure cases. Record calls, diagnostic latency, stop reason, evidence count, and fixed failure categories in the [Phase 4 review](../python/evaluation/PHASE4_REVIEW.md). Treat single-run latency as smoke-run evidence, not a benchmark. Phase 5 diagnosis quality and Phase 7 restart safety require separate reviews.
- **Separate diagnosis contract:** Phase 5 starts with a typed result that separates `supported` from `inconclusive`, lists current-evidence IDs per hypothesis, and keeps historical context IDs separate. Diagnosis source and failure fields remain separate from classification source and failure. Runtime validation rejects malformed result fields, unsupported or cross-incident citations, history used as current evidence, and supported hypotheses without a current citation. It checks reference integrity; whether evidence actually proves a cause is a separate diagnosis-policy decision. The contract does not itself produce a diagnosis.
- **Narrow first supported diagnosis:** the deterministic diagnosis node supports only the observed API database login rejection mechanism when current health and log evidence both contain the explicit SQLSTATE 28P01 failure with matching source references. The mock fixture has no cause label. The diagnosis cites both current items and asks why the login was rejected; it does not attribute a credential change or other underlying cause. Missing or conflicting evidence, correlated degradation, failed probes, queue depth, and timeouts remain `inconclusive`. The default classification-only route leaves diagnosis empty, and a reused checkpoint thread clears the prior diagnosis. Diagnosis never changes severity or authorizes remediation.
- **Optional diagnosis adapter boundary:** use the existing optional `llm` dependency and a synchronous, injected structured chat client for diagnosis. Keep provider initialization out of the default graph and SDK retries disabled. The model schema omits workflow-owned source and severity; the future node must assign provenance, validate current-incident citations, repair invalid output at most once, bound transient retries, and fall back safely. The system prompt treats incident and tool text as untrusted data, keeps history separate from current evidence, and requires abstention when observations do not directly support a narrow mechanism. The prompt alone is not a causal-proof validator.
- **Opt-in diagnosis routing:** after the bounded diagnostic loop, `diagnosis_mode = "deterministic"` remains the default and `"llm"` requires an injected diagnosis model. Missing or invalid mode configuration fails before diagnostic reads. The model receives current evidence and separately labeled history, while the node, not the provider, owns source, citation validation, cause policy, retries, and fallback. Diagnosis cannot change final severity.
- **Narrow accepted mechanism and safe fallback:** supported model output must match the current API database login rejection rule with both current health and log citations. Normalize accepted wording to the deterministic mechanism statement so model prose cannot add an unproved underlying cause. Inconclusive output has no hypotheses. Allow one grounded repair of invalid output and at most three attempts for each provider request on transient failures; after failure, return a recorded, validated inconclusive fallback even if the deterministic rule would have supported a mechanism. Record actual model calls, repair, failure reason, and node latency. This favors explicit uncertainty over silently converting a failed model route into a supported claim.
- **Freeze and report Phase 5 comparison:** use separate project-authored development and held-out labels outside the Go fixture store, identical diagnostic snapshots and budgets for three arms, and a fresh checkpoint thread per case/arm. The 2026-11-23 held-out alternate authentication case was missed by all arms, and both model arms repaired then fell back; preserve that result rather than tuning on the frozen case. Labels lack independent review and history usefulness lacks a blinded reviewer, so keep model diagnosis opt-in and make no improvement or production-quality claim. See [PHASE5_REVIEW.md](../python/evaluation/PHASE5_REVIEW.md).
