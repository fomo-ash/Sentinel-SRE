# Decisions

- **Deterministic baseline first:** a small rule set makes state transitions and failure cases testable before model calls. It is not a production classifier.
- **TypedDict state:** follows LangGraph's typed state pattern with minimal dependencies. Runtime input validation is explicit at intake.
- **Optional LangChain:** reserved for provider integration when model calls begin; the foundation requires no API key.
- **In-memory checkpoints:** temporary foundation choice; restart loses state. Durable checkpoints are required before production deployment.
- **Local-only Go server:** avoids exposing simulated remediation endpoints when they arrive.
- **Separate LLM interpretation and policy:** structured model output will report interpreted impact and uncertainty; deterministic policy will enforce severity. Model output cannot invent metrics.
- **Ground severity in the current report:** the severity policy keeps a known baseline result unless the report explicitly negates that scope. When the baseline is `unknown`, it accepts only verbatim source references from the incident summary and maps their scope with fixed rules. Unsupported, missing, negated, or conflicting impact remains `unknown`; a model's recommended severity never grants remediation approval. The fixed scope vocabulary has the same paraphrase limitations as the baseline.
- **Validate classifier output at runtime:** retain a separate `TypedDict` output contract and use Pydantic's `TypeAdapter` to enforce types and an optional confidence range of 0–1. Declare Pydantic and typing-extensions directly because the schema uses them.
- **Inject the classifier model:** keep the model call behind a small `Protocol` so fake-model tests run without credentials. Return interpreted output separately from graph state and severity policy.
- **Optional OpenAI adapter:** use LangChain's OpenAI integration behind the existing model protocol. The system prompt requires exact report quotes for impact claims; LangChain requests structured output, and Pydantic still validates the result. Disable provider-internal retries so the classification node owns the bounded retry count. Require explicit model and API-key environment variables only when constructing the adapter.
- **Explicit model routing:** the graph always computes the baseline first, then routes to the model only for `classification_mode = "llm"` with an injected model. Both routes pass through deterministic severity policy. A missing model or unrecognized mode fails visibly; the default route remains local.
- **Bounded classification recovery:** repair invalid structured output with at most one grounded model retry; retry each transient provider call at most three times with exponential backoff. A future provider adapter must translate temporary rate limits or unavailability into `TransientProviderError`. After exhaustion, record the reason and use the deterministic baseline, keeping ambiguous impact `unknown` for human review. Classification is never remediation approval.
- **Historical retrieval is context:** similar past incidents can guide questions but cannot prove current impact or cause. Start with a local sentence-transformer and in-memory ranking; defer pgvector until evaluation supports it.
- **Evaluation before claims:** compare baseline, LLM, and LLM plus retrieval on fixed synthetic labels, with latency and failure measurements alongside quality metrics.
- **Keep model routing opt-in after Phase 2:** the frozen v1 run favored GPT-6 Luna on final severity, but the separate challenge run had low severity accuracy and weaker symptom precision. Both sets are small and synthetic; the challenge set was also used for a policy correction. Keep the baseline default and make no generalization or production-performance claim. Record provider rates as explicit evaluator inputs, not hard-coded prices.
- **Freeze evaluation v1:** keep the 24-case dataset and its reference labels unchanged after the baseline review; make a new version for corrections so comparisons remain reproducible.
- **Single graph:** conditional routing and bounded cycles are sufficient for this workflow; no multi-agent abstraction is needed.
