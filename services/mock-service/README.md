# Mock service

Requires Go 1.22 or newer. Run `make run` and request `curl http://127.0.0.1:8080/health`. The process health endpoint returns `{"status":"ok"}`. Use `SENTINEL_MOCK_SERVICE_PORT` to change the port. The server binds to `127.0.0.1` only. Run `go test ./...` for fixture and HTTP contract tests.

The three Phase 4 diagnostic reads are `GET /incidents/{id}/health`, `GET /incidents/{id}/metrics`, and `GET /incidents/{id}/logs`. For example, `curl http://127.0.0.1:8080/incidents/diag-degraded/health` returns a fixed synthetic observation with `incident_id`, `service`, `observed_at`, `status`, and bounded `checks` (`id`, `status`, `detail`). `curl http://127.0.0.1:8080/incidents/diag-degraded/metrics` returns a matching snapshot with bounded numeric metrics (`id`, `name`, `value`, `unit`, `window`). A window such as `5m` is a duration string. `curl 'http://127.0.0.1:8080/incidents/diag-degraded/logs?limit=2'` returns up to two fixed log entries with stable IDs, timestamps, components, levels, and messages. Logs default to 20 entries and allow at most 50; invalid limits return 400 with `{"error":"invalid_limit"}`.

The fixture IDs are `diag-healthy`, `diag-degraded`, `diag-db-auth`, `diag-db-auth-alt`, `diag-missing`, and `diag-unhealthy`. `diag-db-auth` has explicit synthetic database login rejection observations in health and logs, plus a connection-failure metric. `diag-db-auth-alt` is a separate Phase 5 challenge fixture with the same observed failure mechanism expressed through different IDs and wording. `diag-missing` returns `unknown` health with no checks and empty metrics and logs lists. Empty metrics or logs means no observation, not a measured zero. Unknown IDs return 404 with `{"error":"incident_not_found"}`; invalid IDs return 400 with `{"error":"invalid_incident_id"}`. Go's `GET` route pattern also accepts HEAD; mutation methods such as POST are rejected.

Fixtures contain observations only, with no cause or severity labels. Python's opt-in graph can read them and produce a cited diagnosis; remediation is not implemented. The incident metrics are fixed fixtures; this service does not run Prometheus or expose process instrumentation at `/metrics`.
